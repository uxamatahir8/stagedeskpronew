# Client feedback review (CF-01 … CF-17)

Branch `feat/client-feedback-production-hardening`, based on `staging` at
`1c604685229785ef8c99fb6f5a6cab1e8acf86f7` (PR #6 merged). For every item: what
the client saw, what the code actually did, the root cause, and what changed.
File references are to the branch.

Status legend: **Done** = implemented and covered by automated tests that were run;
**Done (UI unverified)** = server side tested, browser flow written but not run
green in this session (see the test matrix).

The add/edit form's **Condition** select (good/fair/poor) looked like the place for it. | Every inventory list row has **Report defect** (reason required; reservations released only after confirmation, through the existing `reconcileReservations`) or **Repaired** (`RowDefectAction`). Single create/edit also refuse duplicate serials. | Done |
| CF-03 | Equipment should be an option on a booking | Packing lists and packages existed (`/app/bookings/[code]/equipment`), but the booking page only had a small sidebar box. | Equipment is a main-column section with the first lines, reservation warnings and **Add equipment or package**.
